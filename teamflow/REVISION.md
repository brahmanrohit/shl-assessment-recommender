## 1. The project in one breath

REST API for team project management. HTTP request → **Resource** (speaks HTTP)
→ **Service** (business rules + transactions) → **Repository** (DB access)
→ **MySQL**. JSON shaped by **DTOs**, runs in **Docker**, tested in **CI**.

**Stats:** Java 21 · Quarkus 3.15 · 5 entities · 20+ endpoints · 43 tests · 7 phases.

---

## 2. Quarkus

- **What:** Java backend framework (like Spring Boot, newer).
- **Why:** container-first — build-time work → millisecond startup, low memory → ideal for Docker/K8s/serverless.
- **Spring mapping:** @RestController→Resource, @Service→Service, @Repository→Repository.

## 3. REST basics

- **Resource** = a thing at a URL (`/api/tasks`).
- **Verbs:** GET read · POST create · PUT update · DELETE remove.
- **Status codes:** 200 OK · 201 Created · 204 No Content · 400 bad input · 401 not logged in · 403 not allowed · 404 not found · 409 conflict (duplicate email) · 500 server bug.

## 4. Layered architecture

| Layer | Job |
|---|---|
| Resource | map URL+verb → method, return correct status |
| Service | business logic, @Transactional |
| Repository | database only |
| Entity | Java class ↔ DB table |
| DTO | JSON shape in/out (never expose entities) |

**Why split:** one reason to change per layer; testable; swap MySQL → only repository cares.

## 5. ORM: JPA/Hibernate + Panache

- **ORM** maps class→table, field→column. Panache gives `persist() findById() listAll() deleteById()` — no hand-written SQL for CRUD.
- **Key annotations:** `@Entity` `@Id` `@GeneratedValue(IDENTITY)` (MySQL auto-increment) · `@Column(nullable,length)` · `@Enumerated(STRING)` (store "TODO" not 2) · `@PrePersist` (stamp createdAt).
- **Still know SQL:** `quarkus.hibernate-orm.log.sql=true` shows every real SELECT/INSERT.

## 6. Dependency Injection

- Never `new TaskRepository()` — Quarkus builds objects and wires them (CDI/Arc).
- `@ApplicationScoped` = one shared instance. Constructor injection = ask for what you need.
- **Why:** loose coupling; swap a fake repo in tests.

## 7. Validation (trust boundary)

- Rules on the DTO: `@NotBlank @Size @Email @Positive @FutureOrPresent`; `@Valid` in the resource triggers them → 400 with field errors **before** business logic.

## 8. Transactions

- `@Transactional` on service methods: all DB ops succeed or ALL roll back. No half-created data.

## 9. Error handling

- Exceptions carry their status (`ApiException` base with `int status`); **one** `ApiExceptionMapper` renders them all as standard JSON (JAX-RS picks the nearest-superclass mapper). Consistent shape, no stack-trace leaks.

## 10. Docker

- **Container** = app + everything it needs → runs identically everywhere.
- **Multi-stage Dockerfile:** stage 1 Maven build, stage 2 only app + small JRE → lean, safer image.
- **Compose:** app + MySQL + LocalStack on one network; app reaches DB at host `mysql` (service name), not localhost.

## 11. Kubernetes + AWS vocabulary

- **Pod** = one running container · **Deployment** = keep N alive, restart dead ones · **Service** = stable address in front.
- **AWS map:** ECS/EKS run containers · RDS = managed MySQL · S3 = file storage · ECR = image registry.
- **Deploy answer:** build image → push to ECR → run on ECS/EKS → point config at RDS → uploads to S3.

## 12. Auth — Phase 1 (the big one)

- **Authentication** = who are you (login). **Authorization** = what may you do (roles).
- **401** = don't know you (no/bad token). **403** = know you, not allowed.

### Passwords
- Store **BCrypt hash**, never the password. Hashing = one-way (encryption is two-way = wrong for passwords).
- BCrypt = deliberately **slow + salted** → stolen hashes are expensive to crack (SHA-256 is too fast).
- Login error is vague ("Invalid email or password") — precise errors leak which emails exist.

### JWT
- `header.payload.signature`. Payload = claims: sub (id), upn (email), groups (role), exp, iss — readable by anyone, **never put secrets in it**.
- Signed with **private key**, verified with **public key** (RS256, 24h expiry).
- **Stateless** → no session store → any pod verifies alone → horizontal scaling.

### Protected request flow
`Bearer token → signature+expiry+issuer check (else 401) → @RolesAllowed groups check (else 403) → method runs`. Declarative — we wrote zero filter code.

### Design decisions
1. Signup can't pick a role (no privilege escalation).
2. First admin bootstrapped at startup from env vars (chicken-and-egg solved).
3. Keys gitignored — generated by script + Docker build; prod would use a secret manager.
4. `UserResponse` has no passwordHash field — DTOs guarantee no leak.

## 13. Relations + N+1 — Phase 2

### Schema
`users ─owns→ projects ─contain→ tasks ─have→ comments; tasks.assignee→users (optional)`.
Every arrow = a **foreign key**; DB refuses orphan rows (referential integrity).

### Annotations
- `@ManyToOne` on the child owns the FK column (`@JoinColumn`).
- `@OneToMany(mappedBy=...)` = mirror side, no second FK.
- Delete cascade is **DB-level** (`@OnDelete CASCADE`): one DELETE kills the subtree — faster than JPA's row-by-row cascade.

### LAZY vs EAGER
- LAZY everywhere: related row loads only when its **data** is touched.
- Subtlety: on a lazy proxy `.getId()` is FREE (id already in the FK column); `.getDisplayName()` hits the DB.

### N+1
- Naive: 1 query for 100 tasks + 100 lazy loads while mapping = 101 queries.
- Fix: `join fetch` (LEFT for optional assignee, else rows silently drop). **Measured: exactly 1 SELECT** in the SQL log.

### Ownership (object-level auth)
- @RolesAllowed answers "what role"; ownership answers "is THIS one yours".
- `ProjectService.findAccessible()` = single gatekeeper: 404 unknown, 403 not yours, admin bypass. Tasks/comments/attachments all delegate to it.
- Skipping this = BOLA/IDOR, the OWASP #1 API vulnerability.

## 14. Pagination — Phase 3

- **Why:** unbounded lists OOM the app and lock the DB. Every list endpoint bounded, cap 100.
- **Envelope:** `{content, page, size, totalElements, totalPages}` — one generic `PageResponse<T>`.
- **Underneath:** `LIMIT/OFFSET` + a second `COUNT(*)` query = 2 queries per page (measured). Deep OFFSET degrades → keyset pagination is the scalable upgrade.
- **Stable order:** every ORDER BY ends `, id` — equal values otherwise shuffle between pages (duplicates/gaps).
- **Sort whitelist (security):** `?sort=` goes into ORDER BY → map allowed names through a whitelist, 400 for everything else. Raw user input never touches the query string.
- **Hygiene:** page<0→0, size clamped 1..100, out-of-range page → empty content + real metadata, still 200.

## 15. S3 attachments — Phase 4

- **Files don't belong in DBs:** blobs bloat backups/replication/RAM. FILE → S3, metadata row (name, type, size, s3_key) → MySQL. Key never leaves the server.
- **LocalStack:** local AWS clone in compose; same SDK calls as real AWS — prod switch = endpoint + credentials, zero code.
- **Presigned URLs:** API authorizes → signs a 15-min URL → client downloads DIRECTLY from S3. No app memory/bandwidth per download; links self-expire.
- **Upload validation:** 5 MB cap, content-type whitelist, sanitized filename, key = `task-{id}/{uuid}-{name}` (no collisions, no path tricks).

---

## 16. Flyway — Phase 5

- **Why:** auto-generated schema (`drop-and-create`) erases data on restart — never in prod. Schema changes only via versioned SQL migrations.
- **How:** `V1__init.sql` (dumped from the Hibernate-built schema — neat adoption trick). Flyway applies unapplied files in order, records them in `flyway_schema_history`, checksums them. **Never edit an applied migration — add V2, V3…**
- Hibernate switched to `validate`: entities must match the real schema or boot fails. SQL owns the truth.
- **Bonus fix:** ids never reset → old JWTs can't point at a different user after restart.

## 17. CI/CD — Phase 6

- `.github/workflows/teamflow-ci.yml` (repo root, path-filtered to `teamflow/**`): checkout → JDK 21 + Maven cache → generate JWT keys → `mvn verify` (43 tests) → docker build.
- **Key enabler:** datasource config scoped to `%prod.` → in test/CI Quarkus **Dev Services** auto-starts throwaway MySQL + LocalStack containers.
- **Why CI:** every push proven green before merge; red build = don't merge.

## 18. Observability — Phase 7

- **/q/health/live** — process alive? Fail → K8s KILLS + restarts the pod.
- **/q/health/ready** — can I serve now? Includes auto DB check. Fail → K8s stops routing traffic, does NOT restart.
- Mixing them up = restart storms (a DB blip reboots the whole fleet).
- **/q/metrics** — Prometheus format, zero code: request rate/latency per endpoint, JVM heap, GC. The 3 numbers: **Rate, Errors, Duration (RED)**.
- Custom health check only for deps the framework can't see (e.g. S3 reachability).

## 19. The 24 interview answers (one line each)

1. **POST /api/tasks flow?** Resource → DTO + @Valid → Service in transaction → Repository persist → 201 + JSON.
2. **Why layers?** Separation of concerns, testability, one responsibility each.
3. **What's an ORM?** Maps Java objects ↔ tables; work with objects, not raw SQL.
4. **Invalid input?** Bean Validation on DTO + @Valid → 400 with field errors.
5. **Transaction?** All-or-nothing group of DB ops; keeps data consistent.
6. **Why Docker / multi-stage?** Same image everywhere; build stage + slim runtime stage = small secure image.
7. **How does login work?** BCrypt-verify → signed JWT with id+role → Bearer header → signature check + @RolesAllowed.
8. **Why JWT over sessions?** Stateless — any pod verifies with the public key; scales horizontally.
9. **401 vs 403?** 401 not authenticated; 403 authenticated but not allowed.
10. **Why BCrypt not SHA-256?** SHA is fast (billions of guesses/sec); BCrypt slow + salted.
11. **One-to-many in JPA?** @ManyToOne child owns FK + mappedBy mirror; LAZY; cascade only for shared lifecycle.
12. **N+1?** 1 list query + N lazy loads; fix with join fetch; verify in SQL log.
13. **Stop users reading others' data?** Object-level auth: resolve resource, check owner vs JWT id — 404/403.
14. **Why seed in Java not import.sql?** Rows need BCrypt hashes + FK chain; SQL can't hash — startup bean, env-toggled.
15. **How to paginate?** page/size (capped), LIMIT/OFFSET + count query, standard envelope.
16. **Safe sorting?** Whitelist maps API names → columns; anything else 400; input never reaches the query.
17. **Why ORDER BY ends with id?** Deterministic tiebreaker — else duplicates/gaps across pages.
18. **Pagination cost?** 2 queries/page; deep OFFSET degrades → keyset pagination.
19. **Where do files go?** S3; MySQL holds metadata + key; downloads via presigned URLs.
20. **Why presigned URLs?** API only authorizes + signs; S3 serves the bytes; links expire.
21. **Prod schema change?** New versioned migration; Flyway applies once, history table replays everywhere.
22. **Hibernate validate?** Boot-time check entities == schema; migrations own the schema.
23. **Liveness vs readiness?** Liveness = restart if stuck; readiness = hold traffic (DB down/warming). Confusing them = restart storms.
24. **Monitoring in prod?** Prometheus scrapes /q/metrics → dashboards + alerts on rate/errors/latency; health endpoints drive probes.
